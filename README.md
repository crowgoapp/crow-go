# Crow Go

منصة ويب (PWA) للسماسرة والوسطاء الميدانيين في مصر — عقارات، عربيات، دليفري
وغيرها. الوسيط بيسجل عروضه وبيانات المالك بشكل سري، يطلع بوستر كتالوج مجمع
بأكواد لنشره على واتساب وفيسبوك، يتابع طلبات الزبائن، ويدير اشتراكه وإحالاته.

هذا الفرع (`fix/security-and-reliability`) يطبّق الإصلاحات الواردة في تقرير
فحص الكود بتاريخ 2026-11-20 (29 مشكلة: 5 حرجة، 7 عالية، 9 متوسطة، 8 منخفضة).
راجع [`docs/fixes-applied.md`](docs/fixes-applied.md) لمعرفة أي مشكلة اتصلحت في
الكود وأيها محتاجة خطوة يدوية منك في لوحة Supabase.

## البنية التقنية

- **الواجهة:** HTML/CSS/JavaScript عادي (Vanilla)، من غير Framework أو أداة بناء.
- **الخلفية:** [Supabase](https://supabase.com) — Auth، Postgres، Storage.
- **توليد الصور:** [html2canvas](https://html2canvas.hertzen.com/).

## خريطة الملفات

| الملف | الدور |
|---|---|
| `index.html` | كل الشاشات والنوافذ المنبثقة |
| `app.js` | الاتصال بـ Supabase، أدوات مساعدة، الدخول/التسجيل، الأدمن |
| `waseet.js` | قلب التطبيق: العروض، البوستر، الطلبات، الاشتراك، الإحالات |
| `admin.js` | لوحة السوبر أدمن (الوسطاء + المدفوعات قيد المراجعة) |
| `style.css` | كل تنسيقات الواجهة |
| `manifest.json` | إعدادات PWA |
| `service-worker.js` / `offline.html` | تثبيت على الموبايل + دعم محدود بدون نت |
| `supabase/migrations/*.sql` | **لازم تتشغل يدوياً** على مشروع Supabase بتاعك |
| `supabase/functions/admin-reset-pin/` | Edge Function لإعادة تعيين PIN وسيط (تحتاج نشر يدوي) |

## التشغيل محلياً

التطبيق ملفات ثابتة بالكامل، مفيش build خطوة:

```bash
python3 -m http.server 8080
# أو: npx serve .
```

ثم افتح `http://localhost:8080`.

## إعداد Supabase (مطلوب قبل أول تشغيل حقيقي)

> ⚠️ **لا تُشغّل أي خطوة من دي على مشروع Supabase الحقيقي (الإنتاج) مباشرة.**
> أنشئ مشروع Supabase منفصل للتطوير أولاً، وجرّب عليه، وراجع كل حاجة قبل ما
> تطبّقها على الحقيقي.

1. **الجداول (Schema):**
   - **مشروع جديد فاضي (مُستحسن — بيئة التطوير المنفصلة):** `0000_initial_schema.sql`
     بيبني الجداول الستة (`profiles`, `products`, `product_images`, `orders`,
     `payments`, `referrals`) + trigger بينشئ بروفايل تلقائي عند التسجيل
     (كود إحالة + أسبوع تجربة مجاني)، بناءً على ما استنتجه التقرير من الكود
     وما لاحظناه فعليًا أثناء الاختبار.
   - **المشروع الحقيقي الحالي:** الجداول موجودة بالفعل. **متشغلش
     `0000_initial_schema.sql` عليه من غير مراجعة.** صدّر الـ schema
     الحقيقي أولاً (`supabase db dump --schema public`) وقارنه بالملف، وعدّل
     أي فرق قبل ما تكمل على باقي الـ migrations.
2. **تشغيل الـ migrations بالترتيب الرقمي** (`0000` ثم `0001` ثم `0002`):
   ```bash
   supabase link --project-ref <project-ref>
   supabase db push
   ```
   أو الصق محتوى كل ملف SQL في SQL Editor بالترتيب.
3. **إنشاء أول أدمن** (خطوة يدوية، مش ممكنة بـ SQL عادي لأن الجدول مقفول
   بالكامل بـ RLS من غير policy قراءة):
   - اعمل حساب في **Authentication > Users** بإيميل وباسورد قويين (مش رقم
     موبايل وهمي).
   - شغّل في SQL Editor:
     ```sql
     insert into public.admins (user_id) values ('<auth.users.id بتاعك>');
     ```
4. **إيقاف "Confirm Email"** من Authentication > Providers > Email — طالما
   التطبيق لسه بيسجل الوسطاء بإيميل وهمي (`<phone>@crowgo.local`) بدل إيميل
   حقيقي، تفعيل تأكيد الإيميل هيكسر التسجيل والدخول بصمت (كانت المشكلة C5 في
   التقرير). الحل الأقوى على المدى الطويل: تسجيل بـ OTP عبر SMS/واتساب
   (Supabase Phone Auth).
5. **تفعيل CAPTCHA** (Turnstile أو hCaptcha) من Authentication Settings، عشان
   الـ PIN المكون من 6 أرقام ميتعرضش لمحاولات تخمين آلية.
6. **نشر الـ Edge Function:**
   ```bash
   supabase functions deploy admin-reset-pin
   ```
7. **مراجعة Security Advisor** في لوحة Supabase بعد كل الخطوات دي.

## الحدود المعروفة بعد هذا الفرع

- كل الإصلاحات اللي محتاجة قاعدة بيانات حقيقية (RLS، الدوال، الـ Edge
  Function) **مكتوبة وجاهزة لكن مش مطبّقة** — محتاجة تشغّلها بنفسك كما فوق.
- التطبيق لم يُختبر end-to-end على مشروع Supabase حقيقي من هذه الجلسة (لا
  توجد بيانات اعتماد لقاعدة بياناتك، ولا ينبغي أن تُشارك مفتاح service role مع
  أي أداة).
- اختبار البوستر العربي تم على Chrome فقط؛ لازم تتأكد بنفسك على Safari
  (آيفون) ومتصفح واتساب/فيسبوك الداخلي.
- أيقونة الـ PWA الآن لها حجمين صحيحين (192 و512) لكن بدون نسخة "maskable"
  بهامش آمن حقيقي — ده يحتاج تصميم، مش مجرد تصغير الصورة.
- لم يتم اختبار تغليف PWA كـ APK (TWA) أو النشر الفعلي على دومين.

راجع قائمة اختبار القبول الكاملة في التقرير الأصلي (قسم 11) قبل أي إطلاق فعلي.
